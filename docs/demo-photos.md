# Demo photographs

Every package on the site currently shows a **cover photo and a four-picture
gallery that are not real photographs**. They were generated by an image
model (ElevenLabs, `bytedance-seedream-5-pro`) on 29 September 2026 and
depict no actual place.

They exist so the site reads as finished while the agency's own photography
is gathered. **They must be replaced before the site takes real bookings.**

## Why they are deliberately generic

None of the thirteen images purports to be a named landmark. There is no
Tiger's Nest, no Punakha Dzong, no specific hotel. They are a valley, a pass,
a courtyard, a bridge — the kind of scene that is true of Bhutan generally
without being a claim about a particular building someone is about to book a
trip to see.

That restraint is the whole safety argument. A traveller choosing a trek on
the strength of a photograph of a mountain that does not exist has been
misled in a way that a generic valley does not manage. Keep it that way if
more are ever generated: no named places, no specific properties.

They live in `public/media/packages`, so the URLs are same-origin: nothing
breaks if a third-party image host goes away, and they deploy with the app.
1600×900 WebP, about 3 MB for the set.

## Replacing them

Per package, in the admin: **Package tours → (a package) → Edit**. The
**Cover photo** field sets the banner; the **Gallery** section below it sets
the photo set. Saving either replaces the demo value for that package.

The seed script leaves a package alone once it has a real cover or gallery,
so re-running it will not undo hand-entered photography.

## Clearing them all

```sql
UPDATE "Itinerary" SET "coverPhotoUrl" = NULL
WHERE "coverPhotoUrl" LIKE '/media/packages/%';

DELETE FROM "ItineraryPhoto" WHERE url LIKE '/media/packages/%';
```

The `LIKE` matters: it clears only the generated set and leaves any real
photography untouched. Afterwards the pages fall back to their empty states,
which say the photographs have not been published yet rather than showing a
broken frame.

## Regenerating

```bash
npm run db:seed:photos                        # local database
npm run db:seed:photos -- --allow-production  # anything else, deliberately
```

Deterministic per slug, so re-running produces the same assignment rather
than reshuffling the site's appearance. `--replace` overwrites covers and
galleries that already exist, **including real ones**.
