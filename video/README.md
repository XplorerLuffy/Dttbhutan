# How I Built DTT Bhutan — a Remotion case study

A 3m40s developer case study: the idea, the website, the travel platform, and
then the AI Travel Assistant built and integrated into it afterwards.

```bash
cd video
npm install
npm run studio     # scrub the timeline
npm run render     # out/dtt-bhutan-build-story.mp4
```

1920 × 1080, 30 fps, 6,600 frames.

---

## The one rule

**Every pixel of website in this video is a photograph of the running site.**
Nothing in `src/scenes/` rebuilds a DTT Bhutan component, approximates its
layout, or stands in for a screen that doesn't exist. Nothing in the AI chapters
shows an answer the product did not give.

That is the whole claim of a case study, and it is easy to break by accident, so
here is exactly where each kind of material comes from and how to re-make it.

### Website footage — `public/captures/`

58 screenshots, taken by `capture-ui.tmp.mjs` and `capture-assistant.tmp.mjs`
driving Chromium over the production build. Public pages, the signed-in
dashboards, the admin screens, the nav mega-menu, the assistant, the chat
widget, and phone-width versions of the ones that matter.

They were taken against `localhost:3311` running `next build && next start` from
this repository, not against `https://dttbhutan.vercel.app`, because the
container these were made in cannot reach that host. Same commit, same build,
same components, same seeded content — the difference is the hostname, which the
browser frame draws separately and labels `dttbhutan.vercel.app`, the site these
pages are. Re-shoot them against the deployed site by setting `CAPTURE_BASE`.

### AI answers — `src/data/productionReplies.ts`

Every word DRUKA says in this film came back from
`https://dttbhutan.vercel.app/api/chat` on 2026-09-30. Real production, real
system prompt, real knowledge base. They are recorded rather than generated at
render time because the render container cannot reach the AI provider, and a
case study must not show an answer the product never gave.

The captures in the AI chapters were made by typing the recorded question into
the real composer and intercepting only the HTTP call, so the pixels are the
real `AssistantThread` and `AiChatWidget` rendering a real production reply.

They are unedited, including where the assistant declines to invent.

### Code on screen — `src/data/codeSnippets.ts`

Generated by `node extract-snippets.mjs` from the repo root, which slices the
lines out of the real files. Each snippet carries its path and starting line
number, both shown on screen, so any frame can be looked up. Re-run it after
changing a source file and the video follows.

### Numbers — `src/data/projectFacts.ts`

Counted, not estimated; the file records the command used for each. A figure
that cannot be counted is not in the film.

### Architecture diagrams

Read off the repository. `src/lib/ai/providers/` holds exactly `ollama.ts`,
`anthropic.ts` and `gemini.ts`, so the film names three providers. There is no
separate backend service, so there is no box labelled "backend".

## Structure

```
src/
├── Root.tsx                     composition + the site's own typefaces
├── compositions/
│   └── DttBhutanBuildStory.tsx  the chapter table and the dissolves
├── scenes/                      one file per chapter
├── components/
│   ├── BrowserFrame.tsx         a window around a real capture (+ PhoneFrame)
│   ├── Cursor.tsx               a pointer that only mimes real interactions
│   ├── CodeWindow.tsx           an editor pane around real code
│   ├── Architecture.tsx         the layers a request really passes through
│   ├── DataFlow.tsx             one request moving through them
│   └── SectionTitle.tsx         the narration
└── data/                        replies, snippets, facts
```

Timings live in one table in `compositions/DttBhutanBuildStory.tsx`, written as
start and end seconds so they can be read against the script without arithmetic.

Fourteen scene files cover the brief's sixteen beats: "The website was working"
opens `AIIntroduction`, because the pivot and the idea it leads to are one
thought; "Final product" and the closing titles are both `Finale`.

## Rendering notes

- **Chromium.** `remotion.config.ts` points at the browser already installed
  (`PLAYWRIGHT_BROWSERS_PATH`) rather than downloading Remotion's own, which
  this container's network policy blocks. Unset it and Remotion manages its
  own, which is the right default anywhere with network.
- **Fonts.** Fraunces and Plus Jakarta Sans — the site's own — are served from
  `public/fonts` by `fetch-fonts.mjs`. A `<link>` to Google Fonts works in the
  studio but not in the render container, and a film that quietly falls back to
  a system face is worse than one that carries its fonts. `Root.tsx` holds the
  first frame until they are ready.
- **Frames.** JPEG, not PNG: 6,600 frames at 1920 × 1080 is the one part of
  this render that can fill a disk, and the difference is invisible after h264.

## What the video does not show

- **Package cards in a reply.** The assistant can render a card for a package it
  looked up, and the code is in `src/lib/ai/cards.ts` — but none of the recorded
  production replies produced one, so there is no honest footage of it and the
  film leaves it out.
- **Flight booking as a finished feature.** `/flights` runs against a demo
  aggregator. The film shows the page and says so.
